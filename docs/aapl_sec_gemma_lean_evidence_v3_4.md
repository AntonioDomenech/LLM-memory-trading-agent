## The only source-format repair

V3.4 changes only complete-submission envelope-family recognition and the
matching raw legacy header-form separator. The production parser must parse
the original response bytes directly. It must not create a SEC-labelled
alias, replace `IMS` with `SEC`, trim the body, normalize line endings, move
sections, repair hashes after transformation, or parse a rewritten copy.

The shared `parse_complete_submission` rule is fixed as follows:

1. Decode and hash the original payload exactly as before. A family token is
   one exact no-attribute ASCII tag, matched case-insensitively:
   `<SEC-DOCUMENT>`, `</SEC-DOCUMENT>`, `<SEC-HEADER>`, `</SEC-HEADER>`, and
   the four corresponding `IMS` tags. Inner tag whitespace, attributes,
   partial names, or lookalike Unicode bytes are not family tokens.
2. If the original decoded text contains none of the four exact IMS family
   tokens anywhere, execute the inherited SEC-only code path unchanged on the
   original payload. This fast route does not tighten SEC root balance,
   duplicates, header selection, errors, hashes, ordering, or offsets.
3. Otherwise locate non-overlapping generic `DOCUMENT` blocks with balanced
   inherited open/close counts. A candidate authenticated content span must be
   the sole balanced `TEXT` section inside one such block, and the bytes before
   that `TEXT` must already contain exactly one nonempty inherited `TYPE` field
   and exactly one inherited positive-integer `SEQUENCE` field. Only the
   content between that authenticated `TEXT` pair may be masked, with equal
   character count, in a position-preserving structural view. A free-standing
   or fake `TEXT` pair in a preamble, header, inter-document gap, suffix, or
   invalid document metadata hides nothing. Nested, duplicate, or unbalanced
   `DOCUMENT`/`TEXT` topology cannot create an authenticated mask.
4. If every raw IMS token was inside an authenticated filing-text span, so the
   structural view contains no IMS family token, execute the inherited
   SEC-only code path unchanged on the original payload. This is the sole way
   an IMS-looking token inside SEC filing text is ignored.
5. If any structural IMS token remains, select the IMS family only when there
   is exactly one opening and one closing `IMS-DOCUMENT`, exactly one opening
   and one closing `IMS-HEADER`, no structural SEC family token, and no
   unmatched, duplicate, cross-family, or reversed marker.
6. Require the IMS root to contain its IMS header and every `DOCUMENT`
   section, require the header to end before the first document, and require
   the root to close after the final document. Opaque bytes before the root or
   after its close remain allowed and remain in the response hash.
7. Extract the root accession with the selected family and require the exact
   same unique reconciliation to the parsed header accession as the inherited
   SEC path.
8. Reuse the inherited header, document, `TEXT`, sequence, filename,
   legacy-missing-filename, identity, hashing, and offset logic on the original
   decoded text without a new date, form, accession, company, body-count, or
   body-value exception.

Tokens inside authenticated filing `TEXT` do not select or mix an envelope
family. They remain literal filing content and remain covered by the
document-text hash. Tokens outside those authenticated spans are never
hidden. A fake, nested, duplicate, malformed, or unbalanced `DOCUMENT` or
`TEXT` structure cannot conceal an envelope token and still pass.

The mechanically cloned v3.4 source adapter changes only its
`_exact_header_sgml_form` rule:

1. A structurally SEC-only response uses the exact inherited v3.3 header
   selection and three raw form patterns unchanged.
2. An IMS response must have the same one exclusive, balanced, correctly
   nested IMS header chosen by the shared rule and no structural SEC envelope
   marker.
3. Its two tagged form patterns remain unchanged. Its plain legacy label may
   have only `[ \t]*` indentation and one or more contiguous same-line ASCII
   space or tab bytes between the colon and value, expressed as `[ \t]+`.
   Every contiguous post-colon horizontal byte belongs to the separator; the
   captured value begins at the first non-space/non-tab byte. No `\s`, carriage
   return, line feed, empty separator, or other Unicode whitespace is admitted
   on this new IMS plain-label path.
4. Across all admitted raw patterns there must still be exactly one match,
   and the captured raw value must equal the expected `10-K` or `10-Q` value
   byte-for-byte. Case changes, trailing whitespace, split-line values, and
   duplicate fields reject.

The repair is family-general. It must not use a branch, table, exception, or
literal keyed to the observed accession, date, form, role ordinal, response
length, response hash, document count, company, filename absence, preamble
length, suffix length, or exact one-tab spelling. It must accept any otherwise
valid legacy IMS complete submission meeting the general grammar and reject
every malformed or mixed envelope regardless of its identity.
