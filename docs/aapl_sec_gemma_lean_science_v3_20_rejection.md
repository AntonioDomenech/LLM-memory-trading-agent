# AAPL SEC/Gemma lean science v3.20 pre-implementation rejection

## Decision

V3.20 is permanently rejected before an `I320` implementation commit, official
one-shot preflight reservation, development attempt, Yahoo request, Ollama
request, Gemma generation, market-value read, prediction, action, return,
performance calculation, confirmation or live-style data open, paid API,
broker action, or real-money action.

The exact twelve-file working candidate exposed an independent contradiction
in the immutable P320 process: one required source/runtime test alone took
1,153.83 seconds, while the inherited single deadline for the complete
qualification, runtime-authority creation, source authentication, request
construction, privacy checks, and final durable seal is only 1,500 seconds.
The prior passing F319 public receipt records another 697.108 seconds for the
three inherited qualification phases. Their measured planning sum is therefore
1,850.938 seconds, already 350.938 seconds beyond the frozen deadline before
the other seven new required tests or any post-qualification work is counted.

Knowingly consuming a once-only preflight that cannot fit its own deadline
would create a predictable failure rather than test the strategy. `I320` is
therefore forbidden, the official reservation remains unused, and V3.20 has no
strategy result.

A separately preregistered V3.21 may retain the exact V3.20 `_strptime`
preload, direct recovery authority, zero-effect recovery rule, authenticated
source, sanitizer, 75 requests, local Gemma model, prompt, Yahoo series,
features, learner, policy, thresholds, transaction costs, chronological stages,
scientific gates, and effect budgets. It may change only the process timing

the corrected direct-recovery composition before its own implementation exists.

The measured V3.21 single-deadline budget should be frozen as:

```text
300 * ceil(1.5 * (697.108 + 2 * 1153.83) / 300) = 4800 seconds
```

The first 1,153.83-second term covers required node 34 inside qualification.
The second conservatively represents the later runtime/source chain that the
official preflight repeats. The 50% margin covers the other new nodes,
filesystem and Git work, durable finalization, and ordinary runtime variation;
rounding is to the next five minutes. This is an 80-minute hard ceiling, not a
target runtime. V3.21 must retain one shared monotonic deadline with no reset,
retry, dynamic extension, or per-phase clock, and must publish a simple
measured estimate from this frozen calculation before consuming its once-only
reservation.

The V3.21 topology must start from the pushed V3.20 rejection commit:
document-only `P321`, then a separately audited `I321`, then once-only `F321`,
and only afterward any authorized development result or pause path. No V3.20
attempt, authority, or result may be invented, resumed, or reinterpreted.
