the stricter `candidate_abandoned` demotion and its fixed terminal code apply.
A missing required post-segment receipt is likewise indeterminate rather than a
scientific result. Either state makes no next Yahoo/Ollama call, opens no later
body, performs no evaluation, and publishes no normal pass/rejection artifact.
A fresh process may authenticate the exact allowed partial state, run
`publication_recovery_pre`, and publish only already-bound redacted bytes, the
deterministic indeterminate demotion of an unreferenced candidate, or one of the
two exact recovery-created-candidate paths above; it can never invent or adopt
a pass.

A crash after a passing binding but before its request intent may restart,
rebind, and execute that still-untouched unit. A crash after an intent but
before its response is durably sealed is indeterminate and may never retry the
request. A crash after a model response is sealed but before the required
segment-post binding is also indeterminate.

## External-effect budgets and pilot

The zero-effect preflight permits no external request. A pushed passing
preflight authorizes only the exact development attempt.

The development attempt reuses the authenticated SEC source and therefore
makes zero SEC requests. A normally completed attempt makes exactly the
inherited six Yahoo requests, four fixed local Ollama identity requests, and
75 no-retry local Gemma generations. A correctly paused-and-resumed attempt
makes eight identity requests; every other successful count is unchanged. No
pull, repair, retry, fallback model, paid service, broker, or real-money effect
is allowed.

In an unpaused run, one two-request version/show probe occurs immediately
before the first generation and a second two-request version/show probe occurs
immediately after the 75th response is durably sealed. A paused run places one
such two-request pre-probe and one two-request post-probe around each physical
model segment, for exactly eight identity requests. No identity request is
silently moved across a segment boundary.

Yahoo requests retain a 30-second absolute deadline. Each local identity
probe has a 60-second absolute deadline. Each non-streaming Gemma generation
has a 900-second monotonic absolute deadline, with the socket timeout narrowed
to the remaining budget so a slow trickle cannot run indefinitely. Each
logical request has exactly one physical request.

The five fixed pilots run first. Their exact order is sealed by preflight. If
`sum(pilot_durations_ns) + 70 * max(pilot_durations_ns)` is strictly greater
than `43_200_000_000_000`, the attempt must durably pause after call five,
publish only the redacted pause artifact, and require a new pushed continuation
preregistration plus the user's fresh explicit permission. Equality does not
pause. If the projection is at or below the threshold, the remaining 70 calls
may continue in the same attempt.

Before starting development, report a simple runtime estimate, prove offline
that the six Yahoo requests can be constructed, and explain that only V3.11 is
running. Model identity is verified only through the budgeted pre/post requests
inside the authorized attempt. Checkpoints must permit clean pause and resume
without replaying a completed external request.

## Result preservation and decision

Every terminal path privately records exact effect counts, runtime/resource use,
the authority and every source/projection/request/model commitment actually
sealed, opened-state Booleans, and a safe terminal code. A path that completed
independent evaluation additionally records extraction validity, row-level
predictions, actions, ledgers, 5/10-basis-point costs,
annual/block/episode diagnostics, no-leverage proofs, continued-learning
changes, controls, and all 22 gate values.

A rejection or indeterminate path that did not complete evaluation never
fabricates those unavailable fields. It uses the exact inherited private
failure-terminal material with no `science_summary`. Its public result has
`evaluation_completed=false`, `science_summary=null`,
`development_gate_passed=null`, `failed_gate_count=0`, and
`failed_gate_names=[]`. Here zero means that no failed-gate list was evaluated;
it never means the gates passed. An evaluated result has
`evaluation_completed=true` and the complete inherited science summary. The
public result exposes only safe available aggregates, hashes, diagnostics,
gates, and effect counts; row-level source, model, market, prediction, action,
and return material remains private.

A development result and central comparison table are committed and pushed
even when development rejects V3.11 or ends indeterminate. Both use the exact
`F -> R` or, after an authorized pause, `C -> R` result topology; the comparison
row labels the safe terminal code and never reports unavailable gate values as
performance. A preflight rejection instead follows the exact `F -> X` topology
above and creates no development result. Confirmation and live-style data
remain closed unless every development gate passes and a new confirmation
preregistration is pushed.

V3.11 can end only as:

- zero-effect preflight rejection;
- development rejection with complete evidence;
- development indeterminate with complete available-effect evidence, explicit
  unavailable science fields, and no performance claim;
- planned long-runtime pause awaiting a pushed continuation and fresh user
  permission; or
- development pass eligible only for a separately preregistered confirmation
  stage.

Historical outperformance, if any, is not reliable-money evidence. A later
confirmation/live-style success still requires prospective paper trading
before any reliable-money claim. Real-money trading remains outside this goal.
